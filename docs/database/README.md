# FloodNet database design

FloodNet uses normalized PostgreSQL accessed through `node-postgres` and parameterized SQL. No ORM is used. The schema keeps official administrative geography separate from operational flood zones.

## Migrations

Migrations are applied in filename order:

1. `001_initial_schema.sql` — identity, reports, alerts, evacuation, evidence and audit tables.
2. `002_auth_session_indexes.sql` — authentication lookup indexes.
3. `003_module_indexes.sql` — module query indexes.
4. `004_refresh_token_rotation_grace.sql` — safe concurrent refresh rotation.
5. `005_national_geography_and_jurisdiction.sql` — Nepal geography, ward associations, officer jurisdiction, report/centre location fields and operational zone metadata.

## Geography model

| Purpose | Tables | Meaning |
|---|---|---|
| Official reference geography | `geo_provinces`, `geo_districts`, `geo_local_levels`, `geo_wards` | Province → District → Local Level → Ward hierarchy used for reporting and routing. |
| Operational areas | `flood_zones`, `flood_zone_wards` | Flood corridors or risk areas that may span administrative wards. Demo zones are explicitly marked with `is_demo_data`. |
| Officer scope | `user_jurisdictions` | One national, province, district, local-level or ward assignment per operational officer. |
| Alert targeting | `alert_zones`, `alert_wards` | Broad operational and precise administrative targets. |

The checked-in `server/db/seeds/data/nepal-geography.json` snapshot contains 7 provinces, 77 districts, 753 local levels and 6,743 wards. Refresh it with `npm run build:geography` when the approved source data changes; review the generated diff before committing it.

## Important constraints

- New reports default to `PENDING_REVIEW`.
- A report and evacuation centre must reference an active ward or operational zone.
- Report and centre coordinates must be supplied as a valid latitude/longitude pair.
- Review notes are required when rejecting a report or requesting more information.
- Occupancy cannot be negative or greater than capacity.
- Available spaces are generated by PostgreSQL.
- Alert expiry must be later than its start time.
- Lower-cased email values are unique through a functional index.
- Operational reads and writes are scoped by the officer's server-side jurisdiction.
- Important state changes are audited in the same transaction as the change.

## Seed data

`server/db/seeds/001_reference_data.sql` inserts roles, facility types and clearly labelled fictional operational zones. `server/db/seeds/001_nepal_geography.js` loads the normalized reference hierarchy and demo zone-to-ward mappings. `server/db/seeds/002_demo_accounts.js` is optional and only runs when a private `DEMO_PASSWORD` is supplied outside production.

Production should run migrations and reference seeds, then create the first real administrator with `npm run db:bootstrap-admin`. Do not use demo accounts or demo zones as production credentials or official geography.
