# Workload ownership

The four primary modules have one accountable owner each.

| Member | Primary role | Main functionality |
|---|---|---|
| Member 1 | Resident | Registration, reporting, report history, resident information views |
| Member 2 | Flood Monitoring Officer | Review queue, verification, alert management, situation dashboard |
| Member 3 | Evacuation Officer | Centre management, occupancy, facilities, evacuation dashboard |
| Member 4 | System Administrator | User management, roles, zones, master data, audit interface |

Shared infrastructure must still have an implementation owner recorded by the team:

- authentication and RBAC
- database migration conventions
- reusable React components
- Elastic Beanstalk and RDS deployment
- Task 2 microservices
- test strategy and evidence collection

Each member's final evidence should identify frontend files, backend routes/services, database tables, AWS components and tests contributed.
