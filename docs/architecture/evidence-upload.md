# Evidence upload architecture

Evidence images are uploaded from the Resident report form after a report has an ID. Task 1 sends image bytes to the existing Express application, which stores them in private S3. Task 2 keeps the same metadata contract but switches the upload responsibility to API Gateway and the serverless Evidence Service.

## Task 1 lifecycle

1. Resident submits the report.
2. FloodNet returns the report ID.
3. React sends the selected multipart images to Express `/api/reports/:id/evidence`.
4. Express verifies report ownership and status, checks file count/size/type and image signatures, and generates safe report-scoped S3 keys.
5. Express uploads the image bytes to the private S3 bucket using its Elastic Beanstalk IAM role.
6. RDS stores evidence metadata only: report ID, uploader, original filename, content type, size, checksum and S3 object key.
7. Express authorizes evidence access and returns a short-lived S3 URL when the report owner requests a photo.

Express uses memory-only multipart handling for the request. It does not write evidence files to the Elastic Beanstalk filesystem.

## Task 2 lifecycle

1. Express still creates a short-lived, report-specific upload session for compatibility with the existing report authorization model.
2. React sends the upload request to the protected API Gateway endpoint.
3. The Lambda authorizer verifies the evidence scope, resident and report claims.
4. The Evidence Lambda validates the file request, creates the safe report-scoped S3 key and returns a short-lived presigned PUT URL.
5. React uploads directly to the same private S3 bucket and calls the existing Express completion endpoint so the compatible RDS evidence metadata record is written.

This preserves the existing `flood_reports` and `flood_evidence_metadata` records while making the file-storage/upload responsibility the serverless evolution in Task 2.

## Rules

- Maximum 5 evidence images per report.
- Maximum 5 MB per image.
- Allowed types: JPEG, PNG and WebP.
- SVG, executable files and arbitrary extensions are rejected.
- S3 keys are generated by the service and never use the original filename.
- Public endpoints never expose evidence metadata or download URLs.
- The S3 bucket is private.
- A report can receive evidence only while it is `PENDING_REVIEW` or `MORE_INFORMATION_REQUIRED`.
